# Calendar sync (staged, not enabled)
Use a private dedicated calendar and a standalone Google Apps Script, no new subscription. Hourly polling is proposed to limit Netlify usage. Existing orders are excluded by setting the start date explicitly at activation; do not assume old paid records are unfulfilled. For standard orders use a provisional two-weekday mailing target (weekends excluded; holidays require manual adjustment). Scheduled orders use the requested date. Completion and cancellation suppress reminders and retain history. Missing/deleted records are not automatically removed; review manually.
1. In script.google.com create a private project, copy docs/calendar-sync.gs, add Calendar advanced service, set timezone America/Chicago.
2. In Project Settings > Script properties set MM_CALENDAR_ID to the private dedicated calendar's ID and MM_START_DATE to agreed YYYY-MM-DD (UTC lower bound). Run generateCalendarToken and copy the private MM_TOKEN value directly into Netlify as CALENDAR_SYNC_TOKEN, secret, production-only, functions scope. Never share the token in chat or commit it.
3. Deploy after checking tests and Netlify usage; endpoint refuses requests without token. Run syncOrders once, verify calendar output, then run installCalendarSync. This makes an hourly Google-owned trigger; no ChatGPT session is required. Review failures in Apps Script Executions. MM_LAST_SUCCESS is recorded in script properties.
4. Verify a second run does not duplicate events; unpaid orders are excluded; verify date/status change, completion/cancellation, and actual reminder settings. No customer letter, name, email or address is transferred. No attendees or invitations. Use a newly created dedicated calendar only. Disable by removing the trigger and revoking token. Existing events are retained.
5. Snapshot cap 500 records; monitor and add pagination before reaching it. The script does not automatically remove events for deleted records. Actual Google permissions and delivery are not verified until installation.
